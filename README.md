# ST Module Engine

Модульный движок для SillyTavern. Расширение берёт на себя конвейер генерации и даёт платформу, на которой строятся модули: трекеры, суммаризация, граф памяти, Prompt Manager, музыка, картинки, синхронизация между устройствами и встроенный ИИ-агент Mea.

Внутри движок устроен как маленькая операционная система. Любая функция оформлена как модуль или ядро, а части системы общаются только через шины контрактов. С SillyTavern работает один слой сервисов, остальной код от клиента не зависит.

Текущая версия: **0.2.1 Beta**.

- Сайт: <https://iamigoi.github.io/index.html>
- Документация для разработчиков: <https://iamigoi.github.io/docs/dev-overview.html>
- Ошибки и предложения: <https://github.com/IAmiGOI/Module-Engine/issues>

## Установка

1. Откройте SillyTavern, раздел **Extensions**, затем **Install extension**.
2. Вставьте адрес репозитория:

   ```
   https://github.com/IAmiGOI/Module-Engine
   ```

3. Нажмите **Install** и перезагрузите страницу.

По умолчанию ставится ветка `Main-Testing`. Движок проверялся на SillyTavern 1.18. Обновления подтягиваются сами при запуске через встроенный механизм SillyTavern.

Beta можно ставить рядом с Alpha: у них разные имена папок и разные точки входа.

## Разработка

### Что нужно

- **Node.js 22 или новее.** В коде используется `Map.groupBy`, на более старых версиях часть тестов упадёт.
- Свежий Chrome, Edge или Firefox для запуска в браузере.
- Для проверки в настоящей среде: отдельная тестовая установка SillyTavern на своём порту, чтобы не трогать рабочую.

Сборки нет. Код пишется на обычных ES-модулях и запускается как есть, без бандлера и транспиляции.

### Быстрый старт

```bash
git clone -b Main-Testing https://github.com/IAmiGOI/Module-Engine.git
cd Module-Engine
npm test
node harness/serve.js
```

После этого откройте <http://localhost:8420>.

`harness/` запускает настоящий движок в обычном браузере, без SillyTavern. Контекст SillyTavern там подменён фейком, который хранит данные в `localStorage` и отдаёт события той же формы, что и настоящий клиент. Через харнесс удобно отлаживать ядра, модули и интерфейс. Если порт 8420 занят, задайте другой: `node harness/serve.js --port=8431`.

### Команды

| Команда | Что делает |
|---|---|
| `npm test` | Все тесты (`node --test`) |
| `npm run typecheck` | Проверка типов по JSDoc во всех файлах с `// @ts-check` |
| `npm run typecheck:progress` | Сколько файлов уже под проверкой типов и где остались ошибки |
| `node harness/serve.js` | Движок в браузере без SillyTavern |

При первом запуске `typecheck` скачивает TypeScript через `npx`. В зависимости проекта он не добавляется: компилятор используется только как проверяющий.

## Архитектура

Движок состоит из пяти слоёв. Подробно они описаны в [docs/architecture.md](docs/architecture.md) и [docs/runtime.md](docs/runtime.md).

| Слой | Папка | За что отвечает |
|---|---|---|
| Runner | `cores/runner` | Запускает систему по порядку: сервисы, библиотеки, ядра, модули. Проверяет права и зависимости модулей, ведёт список того, что не загрузилось и почему. |
| Services | `services/` | Единственное место, где разрешено обращаться к SillyTavern, DOM, сети и таймерам. Каждый сервис отдельным файлом. |
| Libraries | `libraries/` | Чистые функции без состояния и без внешнего мира: разбор, очереди, виджеты, расчёты. |
| Cores | `cores/` | Основная логика движка: модели, память, суммаризация, Prompt Manager, синхронизация, интерфейс. |
| Modules | `modules/` | Функции, которые пользователь включает сам. |

Как отличить ядро от модуля: если без этого кода движок не работает, это ядро. Если пользователь может его не включать, это модуль.

### Шины и контракты

Части системы не вызывают друг друга напрямую. Вызывающий запрашивает возможность по имени контракта, а поставщик регистрирует ответ на него. Шина находит поставщика, проверяет права и доставляет ответ.

```js
import { request } from 'stme:request';

const result = await request(host.cores, 'chatHistory.messages', { params: { limit: 4 } });
if (!result.ok) return;          // в result.error.message написано почему
const messages = result.value;
```

Правила, на которых всё держится:

- **Ответ всегда приходит конвертом** `{ ok: true, value }` или `{ ok: false, error: { message, code? } }`. Исключение не пересекает границу шины никогда: ошибка внутри поставщика ловится и превращается в конверт. `request()` никогда не отклоняет промис.
- **Имя контракта** записывается как `<домен>.<возможность>`, например `model.generate` или `storage.settings.get`. Домен называет возможность, а не конкретного поставщика, поэтому ответить на контракт может любое ядро.
- **Шины разделены по назначению:** события (`host.events`), ядра (`host.cores`), сервисы (`host.services`), сеть (`host.network`). На границах доменов стоят шлюзы, и права проверяются именно там.
- **Сторонний модуль** перед загрузкой проходит статический анализ своего текста и получает уровень доверия. Код при этом не выполняется.

Подробности в [документации по контрактам и шинам](https://iamigoi.github.io/docs/dev-contracts.html), правила именования в [docs/conventions.md](docs/conventions.md).

### Интерфейс

Модуль не работает с DOM. Он возвращает дерево, то есть данные, которые описывают интерфейс, а ядро интерфейса применяет их к странице. Поэтому интерфейс модулей и виджетов тестируется без браузера. Реактивность построена на сигналах (`signal`, `computed`, `effect`), дерево строится через `h()`. Справочник в [документации по UI](https://iamigoi.github.io/docs/dev-ui.html), правила интерфейса в [docs/ui.md](docs/ui.md).

## Как написать модуль

Модуль состоит из одного файла `index.js`. В начале файла стоит заголовок, а по умолчанию экспортируется фабрика.

```js
/*@module
id: community.hello
title: Hello (example)
description: A tiny example module. Safe to remove.
version: 1.0.0
engine: ^0.2
rights: ui.notify
*/
import { h } from 'stme:ui/tree';
import { signal } from 'stme:ui/reactive';
import { Button } from 'stme:widgets';
import { request } from 'stme:request';

export default function create(host) {
    const clicks = signal(0);

    async function sayHello() {
        clicks.set(clicks.peek() + 1);
        await request(host.cores, 'ui.notify', { params: { tone: 'ok', text: `Hello! (${clicks.peek()})` } });
    }

    return {
        async load() {},
        tree: () => h('div', {}, Button('Say hello', sayHello)),
        stop() {},
    };
}
```

Заголовок читается как текст, без запуска кода, поэтому чужой модуль можно проверить заранее.

| Ключ | Значение | Обязателен |
|---|---|---|
| `id` | Уникальный идентификатор. Внешние модули начинаются с `community.`, префикс `module.` занят встроенными | да |
| `version` | Версия по semver | да |
| `title`, `description` | Подписи на карточке модуля | нет |
| `engine` | С какими версиями движка совместим, например `^0.2` | нет |
| `requires` | Зависимости с диапазоном версий, например `module.tracker@^1.0, core.map@>=0.3` | нет |
| `rights` | Контракты, которые модулю нужны, через запятую | нет |
| `network` | `true`, если нужна сеть. Это только запрос, автоматически сеть не выдаётся | нет |

Фабрика `create(host)` вызывается один раз и возвращает объект:

- `load()` вызывается, когда пользователь включил модуль. Здесь восстанавливается состояние и оформляются подписки.
- `tree()` возвращает интерфейс настроек модуля для его карточки.
- `stop()` вызывается при выключении. Здесь нужно снять все подписки.

Импорты вида `stme:...` движок подставляет сам, это входные точки в библиотеки движка. Разобранные примеры от простого к сложному: [Dice](https://iamigoi.github.io/docs/dev-example-dice.html), [Reply Meter](https://iamigoi.github.io/docs/dev-example-meter.html), [Scene Weather](https://iamigoi.github.io/docs/dev-example-weather.html).

## Тесты и типизация

Тесты двух уровней, подробно в [docs/testing.md](docs/testing.md).

- **Юнит-тесты** проверяют одну функцию, ядро или модуль. Всё вокруг подменяется минимальными фейками.
- **Сценарные тесты** поднимают настоящий движок целиком: Runner, шины, шлюзы, ядро прав и модули. Подменяется только слой сервисов, то есть единственная граница с внешним миром.

Правила:

- Название теста записывается полным предложением о поведении.
- Регрессионный тест должен ловить свой баг. Перед коммитом временно откатите исправление, убедитесь, что тест падает с ожидаемым сообщением, и верните исправление.
- Чистая логика выносится в библиотеки, чтобы её можно было вызвать напрямую.

Типы описываются в JSDoc внутри обычных `.js` файлов, без `.ts` и без сборки. Файл включается в проверку строкой `// @ts-check` в самом начале и после этого должен проходить её без ошибок: режим строгий, `@ts-ignore` не используется. Общие типы лежат в `libraries/shared/bus-types.js`, `cores/ui/ui-types.js` и `libraries/core/module-types.js`. Подробно в [docs/testing.md](docs/testing.md#типизация-без-typescript).
