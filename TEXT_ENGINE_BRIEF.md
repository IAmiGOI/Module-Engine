# Бриф: свой раскладчик текста сообщений для Chat Viewport

Задача для внешнего исполнителя (Opus, облачный режим). Репозиторий — ветка `Main-Stable` на GitHub (`IAmiGOI/Module-Engine`). Прочитать перед началом: `ARCHITECTURE.md`, `CONVENTIONS.md`, `NAMING_PHILOSOPHY.md`, `TESTING.md`, раздел «5.94» в `ROADMAP.md` и `tools/text-layout-spike.js` (рабочий эксперимент — отправная точка).

## 1. Зачем

Тело сообщения в WebGL-чате сейчас проходит два разных движка раскладки:

1. **Зеркало** — скрытый DOM-элемент на странице (`styles/chat-viewport/mirror-row.css`): им МЕРИТСЯ высота сообщения (`cores/ui/chat-viewport/body-sync.js`).
2. **Растр** — `services/html-rasterizer.js`: тот же HTML рисуется через SVG `foreignObject` в изображение и загружается в текстуру.

Два независимых движка дают расхождения, которые приходится латать (выравнивание правил абзацев, запас по высоте, подмена шрифта):

- растр — изолированный `data:`-документ, **веб-шрифты страницы (Noto Sans темы ST) в нём не видны** → текст в WebGL рисуется системным шрифтом;
- перенос строк и высота в двух движках расходятся на доли процента (последняя строка обрезалась) — пришлось добавить запас 0,6% + 2px;
- каждое сообщение — это ещё и декодирование SVG и нормализация HTML в XML.

**Цель:** одна раскладка, которую считаем мы сами. Она отдаёт и высоту, и то, что рисовать. Зеркало и SVG-растр для поддерживаемых сообщений уходят; шрифт темы попадает в WebGL-текст.

## 2. Решение (менять только с обоснованием)

Не «движок с нуля» (HarfBuzz/атлас глифов/свой bidi), а **раскладчик строк поверх Canvas 2D**:

- ширины слов — `CanvasRenderingContext2D.measureText` (использует настоящие веб-шрифты страницы, кернинг, лигатуры, эмодзи), с кэшем по (шрифт, слово);
- места переносов — `Intl.Segmenter` (слова, CJK); жадный перенос строк;
- отрисовка — строки/фрагменты `fillText` в 2D-холст (с `text-shadow`, цветами, DPR) → текстура. `webglChat.uploadTexture` (`services/webgl-renderer.js`) уже принимает любой источник для `texImage2D`, в том числе холст;
- **гибрид:** сообщение, разметку которого раскладчик не поддерживает (см. §4), идёт по старому пути (зеркало + SVG-растр) как раньше. Выбор — по белому списку тегов и свойств, на каждое сообщение отдельно.

## 3. Что показал эксперимент (`tools/text-layout-spike.js`)

Наивная раскладка (жадный перенос, `measureText`, правила абзацев как у зеркала) против DOM на 27 реальных сообщениях × ширины 300/389/520/800:

- точное совпадение высоты: **94%**, в пределах одной строки: 96%, средняя ошибка 1,7px; 8 замеров пропущены как неподдерживаемые;
- найденные причины расхождений (учесть в настоящей реализации):
  - `<center>` — блочный элемент с **центрированием строк**; в наброске он не был блоком;
  - **пустые блоки** (`<p></p>`, ST генерирует их между абзацами): у них нулевая высота, а отступы схлопываются — лишний промежуток между соседями добавлять нельзя (margin collapsing);
  - краевые случаи переноса на границе ширины (±1 строка): нужна точная политика пробелов на границе (висящий пробел не считается), длинные слова без пробелов (`overflow-wrap`), неразрывные пробелы, дефисы;
  - пробелы в HTML сворачиваются; `<br>` в конце блока строки не добавляет.

## 4. Границы поддержки

**Обязательно (белый список):** `p`, `br`, `em`/`i`, `strong`/`b`, `q` (цвет цитат, автокавычки убраны — см. `libraries/shared/chat-viewport-body-css.js`), `u`, `s`, `a`, `code` (моно), `pre`, `ul`/`ol`/`li` (маркеры!), `blockquote`, `h1`–`h6`, `hr`, `center`, `font color`, `span` с `style` только из `color`/`font-weight`/`font-style`/`text-decoration`, картинки как коробки (сейчас `dom.prepareImages`, `cores/ui/chat-viewport/body-images.js`).

**Запасной путь (не поддерживать, определять и отдавать старому конвейеру):** таблицы, `details`/`summary`, `flex`/`grid`/`position`/`float`, фоны, рамки, паддинги и любые `span`/`div` с такими стилями, `svg`, `iframe`, `input`/`button`, вложенные произвольные блочные вёрстки. Карточки персонажей часто содержат такую вёрстку — это нормально, они остаются на старом пути.

**Не в объёме:** bidi (право-налево) и сложная письменность — на старый путь; выделение/копирование текста (сейчас его в WebGL тоже нет).

Точка, где придётся учесть **Speaker Colors** (`cores/speaker/index.js`, `modules/speaker-colors/index.js`, `libraries/core/speaker-detection.js`): реплики красятся разметкой, раскладчик обязан читать её так же, как читает растр сейчас.

## 5. Архитектура кода (слои проекта обязательны)

Runner → Services → Libraries → Cores → Modules; подробности — `ARCHITECTURE.md`.

- `libraries/shared/text-layout/*` — **чистая раскладка без DOM**: вход — размеченные фрагменты и `measure(fontSpec, text) → width` (передаётся снаружи), ширина, тема (размер, межстрочный, цвета); выход — `{ height, lines: [{ y, x, runs: [{ text, font, color, x }], align }], boxes: [...] }`. Никаких обращений к `document`/`canvas` — тестируется в Node на фейковой метрике.
- `libraries/shared/text-layout/parse` — парсер подмножества HTML в размеченные фрагменты + **детектор поддержки** (`supported(html) → { ok, reason }`); парсинг через настоящий HTML-парсер браузера, инжектируется (как `normalizeHtmlToXml` в `services/html-rasterizer.js`).
- `services/text-painter.js` (новый Сервис, регистрируется как остальные, контракты гейтятся) — `textPainter.measure` (Canvas 2D `measureText`, кэш), `textPainter.paint({ layout, dpr })` → холст/текстура (плитки, если высота больше лимита текстуры — у `cores/ui/surface/scene.js` есть похожий предел 4096).
- Подключение — `cores/ui/chat-viewport/body-sync.js`: для сообщения, прошедшего `supported`, вместо «зеркало + `htmlRasterizer.rasterize`» — раскладка + `textPainter.paint`; высота из раскладки (без запаса 0,6%). Иначе — как сейчас. Ключ дискового кэша растра (`RASTER_LAYOUT_VERSION`) учесть.
- Стриминг: сообщение перерисовывается на каждый токен — раскладка должна быть дешёвой (кэш измерений слов, пересчёт только изменившегося хвоста, если получится).

## 6. Проверка и критерии приёмки

1. **Страница-сверка** (по образцу `tools/text-layout-spike.js`, но в виде инструмента, который можно перезапускать): для каждого сообщения корпуса и набора ширин сравнивает раскладчик и DOM — число строк по блокам, общую высоту, позиции переносов. Отчёт: доля точных совпадений, максимум, список расхождений.
2. **Корпус:** реальные транскрипты владельца (использовать свободно, спрашивать по каждому не нужно; в тестовом ST на 8010 лежит небольшая выборка — рецепт запуска в `TESTING.md`/памяти проекта) плюс синтетические случаи: списки и вложенные списки, цитаты, код и `pre`, заголовки, `center`, пустые абзацы, эмодзи, CJK, очень длинные слова без пробелов, неразрывные пробелы, `<br>` в начале и конце блока, диалоги с кавычками.
3. **Приёмка:** на корпусе поддерживаемых сообщений совпадение числа строк ≥ 99%, разница высоты ≤ 1px; доля сообщений, ушедших на запасной путь, — отдельной строкой в отчёте (цель: подавляющее большинство обычных сообщений остаётся на новом пути).
4. Юнит-тесты (`node --test tests/`): раскладка на фейковой метрике (фиксированная ширина символа), детектор поддержки, политика пробелов/переносов, схлопывание пустых блоков. Существующие 1987 тестов проходят.
5. Живая проверка визуально: текст в WebGL — шрифтом темы, цвета/тень/цитаты как раньше, последняя строка не обрезана, отступов снизу нет лишних.

## 7. Ограничения проекта

- Файл ≤ 300 строк; дробить по смыслу (`text-layout/` — несколько файлов).
- Слои и шины — по `ARCHITECTURE.md`; UI-тексты — английские; документация и комментарии в этом репозитории — русские; решения фиксируются записью в `ROADMAP.md` (журнал решений).
- Никакой анимации рядом с DOM чата (WebGL-эффекты и `requestAnimationFrame`-циклы вызывают полный reflow — проверено владельцем).
- Не менять поведение старого пути; новый включается только для сообщений, прошедших `supported`.
- Ничего не пушить в `Main-Stable` без явного разрешения владельца; работа — в отдельной ветке/PR.
