# План: музыкальный сервер для ME (разделы + теги владельца)

Решения владельца (2026-10-01):
- Музыку и теги кладёт ТОЛЬКО владелец, через консоль на своём VDS. Теги — «визитка» настроения, как у трека сейчас.
- Пользователь ME видит ОДНО: выбор раздела в карточке Music. Треков, тегов, правки, импорта сервера он не видит.
- Треки приходят по одному и сами: сцена → вектор (локально, `multilingual-e5-small`, `query:`) → косинус с векторами раздела → играет аудио ЭТОГО трека по ссылке.
- Вектор трека (`passage:` от тега) считает СЕРВЕР при загрузке/правке. Наружу уходят только векторы и id — текст тегов не отдаётся.
- Разделы создаёт владелец. Трек лежит в одном разделе.
- Язык: пользователь/ME — только «ME», не «Hermes».

## Формат (v1)
Все GET принимают `?k=<ключ чтения>`, если он задан на сервере (нужен для `<audio>`, заголовок не передать).

`GET /api/sections` → `{ "model": "Xenova/multilingual-e5-small", "dim": 384, "sections": [{ "id": "fantasy", "name": "Fantasy", "tracks": 12 }] }`

`GET /api/sections/:id` → `{ "model": "...", "dim": 384, "name": "Fantasy", "tracks": [{ "id": "k3j9x2", "ext": "mp3", "v": [0.0123, ...] }] }`

`GET /audio/:id.:ext` — файл с `Range`, `Access-Control-Allow-Origin: *`.

Клиент отбрасывает ответ, если `model` не совпадает с моделью ME или длина вектора не равна `dim` (векторы разных моделей несравнимы).

## Порядок
1. Библиотека `libraries/shared/music-catalog.js` + тесты.
2. Ядро `cores/music-server` (единственное с сетью; Модуль в сеть не ходит) + тесты.
3. Модуль Music: выбор раздела, серверные треки отдельно от пользовательских (не сохраняются, не показываются).
4. Сервер `tools/music-server/` (Node, `@huggingface/transformers` — та же модель, q8, те же префиксы) + консоль.
