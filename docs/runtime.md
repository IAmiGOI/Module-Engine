# Runner и модули

Как движок находит, проверяет, загружает и устанавливает модули. Код в `cores/runner/` и в библиотеках `libraries/core/module-*.js`.

## Откуда берутся модули

- **Встроенные** лежат в `modules/*`, их id начинается с `module.`, уровень доверия `official`.
- **Внешние** ставятся из репозитория каталога или по ссылке на GitHub. Их id обязан начинаться с `community.`.

Список включённых модулей хранится в ядре настроек (`core.runner/enabledModules`) и восстанавливается при запуске после того, как появилась панель движка. Незнакомый id при восстановлении пропускается: если модуля больше нет в сборке, запуск не должен падать.

## Заголовок модуля

Отдельного файла манифеста нет. Описание модуля это первый блок-комментарий в его `index.js`:

```js
/*@module
id: community.dice
title: Dice
description: Rolls dice on request.
version: 1.2.0
engine: ^0.2
requires: module.tracker@^1.0, core.map@>=0.3
rights: tracking.poll, ui.notify
network: false
*/
```

- Заголовок читается как текст, без исполнения кода. Чужой модуль можно проверить, не запуская его.
- Обязательны `id` и `version`. У `engine`, `requires`, `rights` и `network` есть значения по умолчанию: пусто и `false`.
- Для встроенного модуля `rights` это набор, который он использует. Для внешнего это запрос: итоговые права решает уровень доверия.

## Порядок загрузки и версии

Runner строит порядок по `requires` (`libraries/core/module-order.js`) и сверяет диапазоны версий по semver (`libraries/core/semver.js`). Если зависимость отсутствует или её версия не подходит, не загружается только этот модуль. Остальные работают, а проблемный попадает в список «Could not load» с причиной.

## Импорты внешнего модуля

Внешний модуль импортирует движок только через `stme:<путь>`, например `stme:ui/tree` или `stme:widgets`. При подготовке исходника движок заменяет их на настоящие адреса. Любой другой импорт (`http(s):`, `data:`, относительный путь за пределы модуля) сканер считает нарушением.

Исполняется ровно тот текст, который был просканирован и хеширован: он загружается через Blob URL, и между проверкой и запуском его нельзя подменить.

## Сканер и уровень доверия

`analyzeExternalModule()` (`libraries/core/module-analyze.js`) разбирает заголовок, сканирует текст (`module-scan.js`) и считает SHA-256. По результату сканирования модуль получает уровень `scanned-safe` или `scanned-unsafe`. Уровень `community` с подписанным ключом предусмотрен архитектурой, но пока не выдаётся.

Песочницы нет: код внешнего модуля выполняется в той же странице, что и SillyTavern. Защита строится на правах через шлюзы, хеше, сканере и карантине, а не на изоляции.

## Установка

1. **Предпросмотр ничего не ставит.** Движок скачивает текст, разбирает заголовок, сканирует, считает хеш и показывает уровень доверия, запрошенные права, запрос сети, находки сканера и какую версию модуль заменит.
2. **Установка** сохраняет модуль вместе с исходником, поэтому для запуска сеть не нужна.
3. **Запуск.** При каждом запуске модуль заново разбирается и сканируется тем же анализатором. Включает его пользователь отдельно.

Ограничения: исходник до 512 КБ. Сеть, запрошенная в заголовке, автоматически не выдаётся.

## Каталог

Репозиторий каталога устроен так:

```
modules/<имя>/index.js    проверенные модули, по папке на модуль, одним файлом
third-party.txt           ссылки на сторонние модули, по одной в строке, # для комментариев
```

Ссылка на сторонний модуль может быть `owner/repo`, URL репозитория, `…/tree/<ref>/<dir>` (берётся `<dir>/index.js`) или `…/blob/<ref>/<файл>.js`.

Адрес каталога пользователь задаёт сам, он хранится в `core.runner/catalogRepository`. По умолчанию это [IAmiGOI/Module-Engine-Modules](https://github.com/IAmiGOI/Module-Engine-Modules), там же README с правилами и пример `modules/hello`.

## Карантин

- Внешний модуль регистрируется с `quarantineOnViolation`. Любой отказ шлюза (контракт вне прав, `http.request` без сетевого права) отправляет его в карантин до конца сессии и записывает `{ id, hash, contract, at }` в `core.runner/quarantinedModules`.
- Карантин привязан к id, а не к хешу. Иначе автору достаточно было бы поменять один байт. Снимает карантин только пользователь кнопкой «Allow again».
- Пока модуль в карантине, он не загружается при запуске, не проходит предпросмотр и виден в «Could not load».
- Встроенные модули в карантин не попадают: их отказ шлюза остаётся обычным отказом в конверте.
