# Директор, часть 8: какие записи лорбука — персонажи, чистые имена, важность, франшиза

**Что не так после части 7** (разбор Claude по коду, `libraries/core/decision-banks.js`):
1. **Персонажи ищутся только по разметке книги.** Раздел `-- … --` со словами character / персонаж / people / cast или префикс `Character:`. В лорбуке владельца злодеи лежат в разделе `-- VILLAINS AND SIN ARCHBISHOPS TYPE SHIT --` и банками не станут.
2. **Имя банка = название записи как есть.** «Rem (Still comatose lmao)» не совпадает с «Rem» в ростере. Прозаик не получит банк, а `ensureName` создаст для «Rem» пустой короткий банк, будто персонаж новый.
3. **Размер у всех записей лорбука — `minor`** (~400 токенов), даже у главных персонажей.
4. **Франшиза субагенту не передаётся** (`canonHint` пуст).

**Решение владельца:** делать. Владелец: **франшиза будет не всегда** — мир может быть оригинальным, и это нормальный случай, а не ошибка.

## Замысел
1. **Разметка лорбука моделью.**
   - При холодном запуске, до сборки банков, директор (его воркер) получает на каждую подключённую книгу список записей: uid, название, ключи, начало текста, разделы книги. Промпт — раздел 11.
   - Директор одним вызовом инструмента `mark_lorebook_characters` отмечает записи-персонажей: `uid`, чистое `name`, `aliases`, `importance` (key / minor), `franchise` (может быть пусто).
   - Разметка хранится в базовом слое с ключом по книге и хешу списка записей (uid + название + текст). Книга не менялась — разметка берётся из хранилища без запроса. Изменилась — размечается заново.
   - **Записи-персонажи = то, что отметил директор.** Нынешний поиск по разделам остаётся **запасным путём**: если воркера директора нет, вызов упал или ответ не разобрался. Тогда — как сейчас, с предупреждением в окне директора.
2. **Чистые имена и алиасы.**
   - Имя банка — `name` от директора.
   - Сопоставление с ростером и `findBankSource` / `ensureName` — по имени и алиасам, без учёта регистра.
   - Новый персонаж ростера получает короткий банк, только если его имя не совпало ни с одним банком по имени и алиасам.
3. **Важность → размер:** `importance: key` → полоса `key`. Уровни 1–2 библиотеки — тоже `key`, как сейчас.
4. **Франшиза:**
   - `canon_hint` берётся из разметки (`franchise`), иначе пусто;
   - **пусто — нормальный случай:** субагент строит банк по источнику и не гадает франшизу (это уже в промпте раздела 10);
   - франшизу из карточки чата не выдумывать: если её нет в данных, она пустая.
5. **Исключение записей-персонажей из текста лорбука** (часть 7, `withoutCharacterEntries`) — по той же разметке: что отмечено персонажем, то идёт банком, а не текстом. Запасной путь — разделы, как сейчас.
