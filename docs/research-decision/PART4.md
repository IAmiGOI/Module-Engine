# Директор, часть 4: два раздела промптов — окно как Prompt Manager

**Что не так после части 3.** Решение владельца было «два раздела, как в Prompt Manager». Claude записал его в задание неверно, и в части 3 получилось **два текстовых поля** в карточке (`cores/ui/panel-cards/decision-card.js`: Director prompt / Writer prompt). Это нужно заменить.

**Как должно быть (владелец, `DIRECTOR-SPEC.md`, раздел «Промпты»):**
- **Окно один в один как окно Prompt Manager**, с двумя разделами: **Director** и **Writer**.
- В каждом разделе есть **закреплённые системные инструкции** (встроенные промпты из `PROMPTS.md`). Их видно, но двигать нельзя.
- В каждом разделе есть **один блок пользователя** — список своих промптов. Внутри блока промпты **двигаются только относительно друг друга**. Весь блок целиком встаёт на автоматическую глубину:
  - у директора — 2 цикла;
  - у прозаика — @5.

  Это размещение из части 3, его не менять.
- Лорбук, историю и прочее в разделах не настраивать. Только свои промпты.

Работа идёт в той же ветке `research/decision`. Она уже совпадает с `Dev-Version`: части 1–3 влиты.

## Решения Claude по составу (владелец может поменять)
**Вернуть из PM:**
- блоки (имя, роль, текст, вкл/выкл);
- группы с обёртками (открывающий и закрывающий тег);
- условия на блоках и группах;
- макросы в тексте;
- предпросмотр итогового запроса раздела;
- пресеты раздела: сохранить, загрузить, дублировать, удалить;
- импорт пресета ST — выбрать, какие промпты из него идут в Director, а какие в Writer;
- экспорт и импорт своего раздела JSON.

**Не возвращать:**
- вкладку CoT — думает директор;
- лорбук, историю, обрезку, бюджеты;
- параметры сэмплера и ризонинга — они у воркеров директора и прозаика;
- текстовые правила, плагины, журнал запросов, переопределения.

## Блоки (коммит на каждый блок, запись в `LOG.md`)

### g0. Разведка
- Что из старого окна и логики PM нужно для состава выше. Что зависело от удалённого Ядра PM (`promptManager.*`) и чем это заменить контрактами `decision.*`.
- **Условия:** какие типы условий старого PM ещё имеют источник данных без PM (длина сообщения, ключевые слова, значения трекера, кулдаун и т. д.). Без источника — не возвращать, записать в `LOG.md`.
- **Макросы:** какие подставлялись (свои ME, ST) и как их подставлять теперь в директоре и прозаике.
- **Хранение:** пресеты разделов — в `storage.settings` (namespace `core.decision`), чтобы бэкап и синхронизация покрывали их без новой категории. Миграция двух полей части 3: если в поле был текст, он становится первым промптом блока.
- План в `DESIGN.md`, раздел «Часть 4».

### g1. Модель и сборка
- Модель раздела:
  - закреплённые системные строки (только чтение, не двигаются, не удаляются, не выключаются);
  - блок пользователя — дерево промптов и групп (двигаются только внутри блока).
- Сборка: включённые промпты блока по порядку, с условиями, макросами и обёртками групп → одна вставка на глубину раздела (2 цикла / @5). Пустой блок или всё выключено — вставки нет, как в части 3.
- Юнит-тесты: порядок, вкл/выкл, группы с обёртками, условия, макросы, пустой блок, миграция двух полей, системные строки нельзя сдвинуть или удалить (модель отказывает).

### g2. Окно
- Окно как старое окно PM, открывается той же иконкой ST «AI Response Configuration».
- Вкладки: **Director**, **Writer**, **Preview**. Предпросмотр показывает раздел целиком: системные инструкции, блок пользователя на своей глубине, места данных директора или прозаика (как плашки, без огромных текстов).
- Системные строки визуально отличаются: замок, другой фон. Перетаскивание на них и через них не срабатывает.
- Пресеты раздела, импорт пресета ST с выбором раздела для каждого промпта, экспорт и импорт JSON.
- Поля из карточки части 3 убрать. В карточке Director / Writer — кнопка «Open prompts», открывающая окно.
- Тесты окна по образцу `tests/prompt-manager-panel.test.js`.
