# Соглашения

Как называются контракты, блоки, события, файлы и идентификаторы, как оформляются комментарии и тесты.

## Протокол

### Контракты

Формат `<домен>.<возможность>[.<уточнение>]`: строчными буквами через точку, составные слова внутри сегмента в camelCase. Примеры: `model.generate`, `model.embed`, `storage.settings.get`, `storage.chatMemory.set`, `worldInfo.entries`, `tracking.value`, `pipeline.run`.

- **Домен называет возможность, а не поставщика.** `model.generate` может реализовать любое ядро, которое умеет генерировать. Заказчик просит возможность и не знает, кто ответит.
- **Имя контракта не меняется в рантайме.** Динамический id в имя не вшивается. Вместо `tracker:field:<blockId>:<name>` используется постоянное имя `tracking.value` и параметры `{ blockId, fieldName }`. Список динамических экземпляров получают через блоки.
- **Внешние модули регистрируют контракты под своим префиксом**, например `community.notebook.inject`. Короткие имена без префикса принадлежат встроенному коду. Так модуль с низким доверием не может выдать себя за официальный `model.generate`.

### Блоки и события

- Блок: `<домен>.<категория>`, например `tracking.blocks`, `picker.insertableValues`, `pipeline.stages`. Категории блоков общие для всего движка: новый модуль берёт существующее имя категории, а не придумывает своё.
- Событие об изменении блока: `<имя блока>.changed`, например `tracking.blocks.changed`.
- События операции: `<контракт>.started`, `.completed`, `.failed` (когда их заводить, описано в [architecture.md](architecture.md#события-started--completed--failed)).

### Ответ

Всегда конверт `{ ok: true, value }` или `{ ok: false, error: { message, code? } }`, на всех шинах и для всех контрактов.

## Файлы и папки

```
cores/<домен>/index.js          например cores/tracking/index.js
modules/<имя>/index.js          например modules/time/index.js
services/<имя>.js               например services/http.js
libraries/core/<имя>.js         библиотеки ядер
libraries/shared/<имя>.js       общие библиотеки
styles/<раздел>/<имя>.css
tests/<имя>.test.js
```

Имена файлов в `kebab-case`. Файл не длиннее 300 строк: если больше, его пора делить по смыслу.

## Код

### Регистр

| Что | Стиль | Пример |
|---|---|---|
| Переменные и функции | `camelCase` | `pickBeacons` |
| Классы и конструкторы | `PascalCase` | `MacroSyntaxError` |
| Константы, которые не меняются | `SCREAMING_SNAKE_CASE` | `MAX_FIELD_LENGTH` |
| Приватные поля класса | `#field`, а не `_field` | `#queue` |

### Префиксы глаголов

Префикс обещает форму функции, поэтому по имени понятно, как она себя ведёт.

| Префикс | Гарантия |
|---|---|
| `resolveX()` | Защитное чтение. Всегда возвращает валидное значение, при плохом входе отдаёт значение по умолчанию, не бросает исключений. |
| `sanitizeX()` | Приводит грязный вход к валидной форме. |
| `computeX()` | Чистая функция: тот же вход даёт тот же выход, без побочных эффектов. |
| `buildX()` | Собирает составную структуру (запрос, промпт) из исходных данных. |
| `applyX()` | Побочный эффект: публикует или сохраняет что-то наружу. |
| `isX()`, `hasX()` | Логический предикат без побочных эффектов. |
| `loadX()` | Асинхронное обращение вовне. Только в сервисах. |

`load` за пределами сервиса означает, что код нарушает границу слоя.

### Структура файла

```
1. Импорты
2. Константы, с комментарием «почему такое значение», если это не очевидно
3. Чистые экспортируемые функции (resolve, sanitize, compute, build)
4. Фабрика или класс ядра, модуля, сервиса
```

Чистые функции выносятся из класса, даже если используются только внутри него. Так их можно проверить тестом, не поднимая ядро целиком.

### Комментарии

- Комментарий объясняет «почему», а не «что». «Что» уже сказано именем.
- Комментарий нужен там, где без него читатель ошибётся: скрытое ограничение, неочевидный инвариант, обход конкретного бага.
- Никаких ссылок на задачи, тикеты и авторов правки. Причина должна быть понятна и через год.
- Комментарии и документы на русском, интерфейс на английском.

### Тесты

Имя теста это полное предложение о поведении, которое он проверяет:

```js
test('get(uid, book) disambiguates two bound books sharing the same numeric uid', ...)
```

Подробнее в [testing.md](testing.md).
