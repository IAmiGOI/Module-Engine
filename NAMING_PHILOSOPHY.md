# ST Module Engine — Beta: философия наименования (весь код движка)

[CONVENTIONS.md](CONVENTIONS.md) — про протокольные имена (контракты/
Блоки/события/манифест). Этот файл — про ВЕСЬ остальной код: идентификаторы,
файлы, структура файла, комментарии, тесты. Закрывает оба открытых вопроса
из CONVENTIONS.md окончательно (см. в конце).

Опирается на то, что уже доказало себя в Alpha (было устойчивой привычкой,
но нигде не задекларировано явно) — здесь это фиксируется как обязательное
правило, не привычка одного автора.

## 1. Лексический стиль по виду идентификатора

- **Переменные/функции** — `camelCase`.
- **Классы/конструкторы** — `PascalCase`.
- **Истинные константы** (никогда не меняются после объявления) —
  `SCREAMING_SNAKE_CASE`: `MODULE_ID`, `DEFAULT_SYSTEM_PROMPT`,
  `MAX_FIELD_LENGTH`.
- **Приватные поля класса** — настоящие `#privateField`, не соглашение
  через `_prefix`.
- **Файлы** — `kebab-case.js`: `data-bus.js`, `lorebook-service.js`.

## 2. Словарь глаголов-префиксов — у каждого ФИКСИРОВАННЫЙ смысл

Не просто стиль — гарантия поведения. Увидев префикс, читатель ЗНАЕТ форму
функции, не читая тело:

| Префикс | Гарантия | Пример из Alpha |
|---|---|---|
| `resolveX()` | Защитное чтение — всегда возвращает валидное значение, при плохом/отсутствующем входе — дефолт, никогда не бросает. | `resolvePollMode`, `resolveBookNames` |
| `sanitizeX()` | Нормализует/фильтрует значение до валидной формы — вход может быть "грязным", выход всегда чист. | `sanitizeFields`, `sanitizeMacroName` |
| `computeX()` | Чистая производная функция — тот же вход всегда даёт тот же выход, без побочных эффектов. | `computeCharacterCardBlocks` |
| `buildX()` | Собирает составную структуру (запрос/промпт) из первичных данных. | `buildTrackerRequest`, `buildLabel` |
| `applyX()` | Побочный эффект — публикует/персистит что-то наружу (в отличие от `compute`). | `#applyPublished` |
| `isX()` / `hasX()` | Булев предикат, без побочных эффектов. | — |
| `loadX()` | Асинхронное обращение вовне — **зарезервировано только для Сервисов** (единственный слой, которому вообще разрешено куда-то обращаться). | `loadWorldInfo` |

Использование `load`/`get`-с-сетевым-подтекстом ВНЕ Сервиса — сигнал, что
код нарушает границу слоя (см. ARCHITECTURE.md).

## 3. Структура файла Ядра/Модуля/Сервиса — единый шаблон

```
// 1. Импорты
// 2. Константы (SCREAMING_SNAKE_CASE) + doc-comment "почему такое значение", если не очевидно
// 3. Чистые экспортируемые функции (resolve/sanitize/compute/build) — тестируемые в изоляции
// 4. Класс/объект самого Ядра/Модуля/Сервиса — activate()/render() как точки входа
```

Чистые функции — ВСЕГДА отдельно от класса, даже если используются только
внутри него: это единственный способ протестировать их без поднятия всего
Ядра/Модуля целиком (проверено на всём объёме тестов Alpha).

## 4. Комментарии — только "ПОЧЕМУ", никогда "ЧТО"

- Имя идентификатора уже объясняет ЧТО — комментарий, повторяющий это,
  не нужен.
- Комментарий пишется только когда без него читатель ошибётся: скрытое
  ограничение, неочевидный инвариант, обход конкретного бага, поведение,
  которое удивит. Если комментарий убрать и читателя это не запутает —
  комментарий не нужен.
- Никогда не ссылаться на текущую задачу/тикет/автора правки в
  комментарии — комментарий переживает контекст, в котором был написан;
  причина обязана быть понятна и через год.

## 5. Тесты — имя теста как полное предложение о поведении

Имя теста описывает ТОЧНОЕ поведение или баг, который проверяется, а не
"testFoo1"/"edge case 2": `"get(uid, book) disambiguates two bound books
sharing the same numeric uid; bare get(uid) returns SOME real match, never
a mix-up"`. Каждый новый регрессионный тест обязан быть проверен на то, что
реально ловит баг (временный откат фикса → тест падает → фикс возвращён).

## Закрытие открытых вопросов CONVENTIONS.md

1. **Неймспейс верхнего уровня — решение через систему прав, не через
   синтаксис.** Плоский `<домен>.<способность>` разрешён ТОЛЬКО для
   official-уровня доверия (первому уровню незачем защищаться от самого
   себя). Начиная с community-уровня, Директор при регистрации **обязан**
   требовать префикс `community.<id-заказчика>.` — так низкодоверенный
   поставщик физически не может выдать себя за официальный домен
   (`model.generate`), только за свой собственный
   (`community.someAuthorModule.model.generate`). Коллизии внутри одного
   уровня доверия по-прежнему ловит сама регистрация на Шине.
2. **camelCase внутри сегмента — окончательно.** Совпадает с обычной
   JS-нотацией доступа к свойствам, не нужно туда-обратно конвертировать
   kebab-case ↔ camelCase на границе кода и протокола.
