# План: обновление окна графа памяти

Документ для исполнителя. Читай целиком перед началом.

**Решения владельца (не менять):**
- Цвет нод по умолчанию — **настоящий вес графа** (важность + связи + затухание; тот же, по которому решается вытеснение), а не голая важность.
- Перетащили ноду внутри её же региона — **возвращается на место** (ручные позиции не запоминаются).
- Регионы — **кольцо секторов вокруг центра**, внутри сектора — узор «подсолнух».
- Подсветка ретрива — **переключатель**, не таймер.
- Уровень ориентира — **карта EVE Online**: несколько режимов карты, высокое качество отрисовки, разные метрики с легендой (этап 6).
 Этапы — **строго по порядку**; после каждого — тесты зелёные, коммит.
Если код расходится с описанием (функция переименована, номера строк другие) — ищи по имени. Если расхождение существенное — **остановись и опиши его**, не придумывай.

Связанный план: `MEMORY_GRAPH_FIX_PLAN.md` (логика графа). Этот план от него не зависит, но этап 2 здесь добавляет в Ядро два небольших API — не конфликтуй с ним: если тот план уже выполнен, просто встраивайся в новые функции.

- Загрузка библиотеки: `libraries/core/graph-rendering.js` — Cytoscape **3.30.2** и `cytoscape-edgehandles` **4.0.1** с jsDelivr.
- Стили окна: `styles/modules/memory-graph.css`.
- Ядро графа (данные): `cores/memory-graph/index.js`; контракты `memoryGraph.nodes`, `memoryGraph.regions`, `memoryGraph.staging`, `memoryGraph.createNode`/`moveNode`/`createEdge`/`deleteEdge` (найди точные имена регистрацией `host.own.register('memoryGraph.` внизу файла).
- Тесты окна: `tests/memory-graph-panel.test.js` — прочитай перед началом, пиши новые по образцу.
- Харнесс для ручной проверки: `node harness/serve.js` → `http://localhost:8420/`; окно графа открывается кнопкой дока.

### Данные, которые рисуем
- Нода: `{ id, label, content, importance (0–10), degree, protectedNode, regionId, edges: [{to, type}], createdAt, … }`.
- Регион: `{ centerNodeId, subCenterIds, nodeIds, sector?, ring?, … }`. **Ключ региона бывает двух видов**: числовой `"сектор:кольцо"` (старая сетка «дартс», 5×3) и **семантический** — любая строка, созданная бутстрапом из лорбука (у реального пользователя почти все регионы такие).
- Нода в накопителе — `regionId === null`.

### Что сейчас сломано (найдено при чтении кода)
- **Б1. Секторы — просто картинка для не тех регионов.** Фон — статичный SVG «дартса» 5×3 (`renderRegionBackgroundSvg`) для числовых регионов. Семантические регионы рисуются по кругу функцией `fallbackSemanticPosition` и **с клиньями дартса никак не совпадают**. При этом перетаскивание и создание определяют регион по клику функцией `pixelToRegion` — по геометрии дартса. Итог: бросил ноду рядом с её семантическим регионом — она переезжает в случайный числовой регион; создал ноду кликом — она попадает туда же.
- **Б2. Ядро умеет создавать и перемещать ноды только в числовые регионы.** `createNodeManually({ sector, ring })` и `moveNodeManually({ id, sector, ring })` проверяют `sector`/`ring` и вызывают `attachToRegion(node, sector, ring)`. В семантический регион руками не попасть вообще.
- **Б3. Полная пересборка на каждое обновление.** `syncCytoscape()` делает `cy.elements().remove()` и добавляет всё заново: сбрасывается выделение и перетаскивание (нода «прыгает» обратно при любом `refresh()`, даже чужом).
- **Б4. Соединение нод фактически недоступно.** `cytoscape-edgehandles` 4.x не показывает «ручку» при наведении — рисование ребра нужно запускать вызовом `eh.start(node)` или `eh.enableDrawMode()`. В коде ни того ни другого нет: `cy.edgehandles({})` создаётся, но пользователь начать соединение не может.
- **Б5. Клик по ребру сразу удаляет его** — случайные удаления.
- Размер всех нод — фиксированные 7px, свечения нет, цвет — только по важности, результат ретрива в окне не показывается вообще (Ядро его никуда не публикует).

## Этап 2. API Ядра: любой регион и публикация ретрива

В `cores/memory-graph/index.js`:

1. **`regionId` в ручных операциях.**
   - `createNodeManually({ label, content, importance, sector, ring, regionId })`: если передан `regionId` и такой регион есть в `regions` → положить ноду через `attachToRegionByKey(node, regionId)`; иначе прежнее поведение с `sector`/`ring`. Несуществующий `regionId` → `{ ok: false, error: 'Unknown region "<id>".' }`.
   - `moveNodeManually({ id, sector, ring, regionId })`: то же самое. Перенос в тот же регион — ничего не делать, `{ ok: true, unchanged: true }`.
   - Слияние/переполнение при вставке работают как обычно (это уже внутри `attachToRegionByKey`).
2. **Имя региона для подписи.** Контракт `memoryGraph.regions` сейчас отдаёт `Object.values(regions)` — **ключа внутри значения может не быть**. Сделай, чтобы у каждого региона в ответе было поле `id` (ключ) и `label` (метка его центральной ноды, `nodes[centerNodeId]?.label`, иначе ключ). Не меняй хранимые данные — добавляй поля только в ответ контракта.
3. **Публикация ретрива.** В `injectIntoPrompt` после вычисления результата (и в ветке «закреплённого» блока, и в обычной):
   ```js
   lastRetrieval = {
     at: Date.now(), sticky: <true если использован закреплённый блок>,
     beaconIds: [...],                               // маяки
     segments: route.segments.map(({ from, to }) => ({ from, to })), // шаги маршрута (каждый — одно ребро)
     standaloneIds: route.standalone,               // маяки без связи
     noiseIds: noise.map(n => n.id ?? n),           // шумовые ноды — посмотри, что именно возвращает expandNoiseNodes, и приведи к массиву id
     query: contextText.slice(0, 200),
   };
   publishEvent('memoryGraph.retrieved', lastRetrieval);
   ```
   Для ветки sticky: маршрута в памяти нет — сохраняй `lastRetrieval` целиком при обычном ретриве и в sticky-ветке публикуй его же с `sticky: true` и новым `at`.
   Контракт `memoryGraph.lastRetrieval` → `lastRetrieval` или `null`. Хранить только в памяти (не в `chatMemory`); при `st.chatChanged` — обнулить.
4. **Вес и метрики нод в ответе `memoryGraph.nodes`** (только в ответе, не в хранимых данных):
   - `weight` — `computeNodeWeight(...)` с тем же `elapsed`, что использует вытеснение (найди, как считает `pickEvictionCandidate`/`elapsedTurnsFor`); у защищённых нод `Infinity` → в ответе `null` и `protectedNode: true` (JSON не умеет `Infinity`);
   - `weightRank` — место ноды по весу среди НЕзащищённых нод всего графа, нормированное в [0, 1] (0 — самая слабая, 1 — самая сильная); у защищённых — `1`;
   - `ageTurns` — сколько «ходов» прошло с `createdTurn`; `idleTurns` — с `lastTouchedTurn ?? createdTurn`.
5. **Счётчик ретривов** (хранимые поля ноды, добавляются мягко — у старых нод их нет, читать как 0/null): в `injectIntoPrompt` всем нодам итогового блока (маяки, маршрут, шум) — `retrievedCount += 1`, `lastRetrievedAt = Date.now()`; маякам отдельно `beaconCount += 1`. Сохранять тем же вызовом, что и `stickyRetrieval` (не отдельным сохранением на ноду).
6. **История ретривов**: вместо одного `lastRetrieval` держи в памяти кольцевой список последних **20** (новые первыми); контракт `memoryGraph.retrievals` → список; `memoryGraph.lastRetrieval` → первый элемент или `null`.
7. Тесты (orchestration): создание и перенос в семантический регион по `regionId`; неизвестный `regionId` — ошибка; `memoryGraph.regions` содержит `id` и `label`; после `injectIntoPrompt` пришло событие `memoryGraph.retrieved` с маяками и `memoryGraph.lastRetrieval` его отдаёт; `memoryGraph.nodes` содержит `weight`/`weightRank` (у защищённой — `null`/`1`); `retrievedCount` растёт у нод, попавших в промпт; история держит не больше 20 записей.

## Этап 3. Раскладка: зоны регионов, динамические радиусы, узор

Новый файл `cores/ui/memory-graph/layout.js` — **только чистые функции, без DOM и Cytoscape**. Это главное место плана: секторы становятся данными, из которых одновременно рисуются фон, подписи, раскладка нод и определяется «куда бросили/кликнули».

### 3.1 Радиус ноды (пункт 2 запроса)
```js
export const NODE_RADIUS = { min: 4, perSqrtDegree: 2.2, max: 16, protectedBonus: 2 };
export function nodeRadius({ degree = 0, protectedNode = false }) // clamp(min + perSqrtDegree·√degree, min, max) + (protectedNode ? protectedBonus : 0)
```
### 3.2 Минимальный зазор — растёт с размером
```js
export const GAP = { base: 4, perRadius: 0.5 };
/** Минимальное расстояние между центрами двух нод: радиусы + зазор, который растёт с большей из двух нод. */
export function minCenterDistance(rA, rB) // rA + rB + GAP.base + GAP.perRadius * Math.max(rA, rB)
```
### 3.3 Раскладка нод внутри региона (пункт 1 — узор)
```js
/**
 * Позиции нод одного региона относительно его якоря (0,0).
 * Центр региона — в якоре. Под-центры — на ближней орбите, равномерно по углу.
 * Обычные ноды — по спирали Фогеля («подсолнух», золотой угол 137.508°): красивое равномерное заполнение.
 * Для k-й обычной ноды угол = k·золотой угол; радиус начинается с радиуса предыдущей ноды и растёт шагом 1,
 * пока до ВСЕХ уже поставленных нод не будет ≥ minCenterDistance.
 * Порядок обычных нод — по createdAt (потом id): новая нода ставится последней и НЕ сдвигает остальные.
 */
export function layoutRegion(members, { centerId, subCenterIds }) // → { positions: Map(id → {x, y}), radius: число — радиус занятого диска }
```
Если центра нет (нода-центр удалена) — якорь пустой, первая по порядку нода занимает якорь.
### 3.4 Зоны регионов (пункт 7 — секторы как данные)
```js
/**
 * Регионы по кругу вокруг центра холста. Каждый регион — кольцевой сектор (зона).
 * Порядок регионов стабильный: по ключу (числовые "s:r" — по сектору, потом кольцу; семантические — по алфавиту).
 * Угол зоны пропорционален площади её диска (radius из layoutRegion + отступ), но не меньше minAngle (12°).
 * Расстояние якоря от центра холста — такое, чтобы диск региона влезал в свой угол: max(innerHole + R, R / sin(половина угла)).
 * Зона: { regionId, label, a0, a1 (радианы), rInner, rOuter, anchor: {x, y}, count, capacity, hue }.
 * hue — оттенок подложки зоны: равномерно по кругу по индексу региона (для различимости, НЕ связан с цветом нод).
```

## Этап 4. Отрисовка: размеры, свечение, цвет по весу, фон-зоны, обновление без пересборки

### 4.1 Обновление без пересборки (Б3)
В окне замени `syncCytoscape()` на **сравнение**:
- посчитать `layoutGraph(...)`;
- ноды/рёбра, которых нет в Cytoscape, — `cy.add`; лишние — `remove`; у существующих — обновить `data` (label, importance, size и т.д.) и **позицию** (`node.position(...)`), кроме ноды, которую сейчас тянут (флаг `draggingId`, ставится на `grab`, снимается на `free`);
- **не трогать** pan/zoom и выделение.
Тест: `refresh()` во время перетаскивания не меняет позицию перетаскиваемой ноды (подмени `cy` фейком с нужными методами — посмотри, как тесты окна уже делают фейковый Cytoscape; если не делают — вынеси сравнение в чистую функцию `diffElements(current, next)` → `{ add, remove, update }` и тестируй её).

### 4.2 Стили (`stylesheet.js`)
- **Размер**: `width`/`height` = `data(size)`, где `size = 2 · nodeRadius(...)`.
- **Цвет по весу**: заливка ноды берётся из `data(color)`, который считает режим карты (этап 6). По умолчанию режим **Weight**: `weightRank` 0 → красный `#e74c3c`, 0.5 → янтарный `#f1c40f`, 1 → зелёный `#2ecc71` (та же логика «сильнее — зеленее», что была у важности). Стили Cytoscape не должны знать про метрики — только `data(color)`, `data(size)`, `data(glow)`.
- **Свечение** (пункт 3) — через подложку Cytoscape (`underlay-*` есть в 3.30):
  `'underlay-color'`: `data(color)`, `'underlay-padding'`: `mapData(size, 8, 34, 3, 10)`, `'underlay-opacity'`: `0.22`, `'underlay-shape'`: `'ellipse'`.
  Защищённые (центр/под-центр): белая обводка как сейчас + `'underlay-opacity': 0.35`.
- **Подписи**: всегда для защищённых нод и нод с `size ≥ 20` при достаточном масштабе (`'min-zoomed-font-size': 8`), для остальных — по наведению (класс `.hovered`, как сейчас). Цвет подписи светлый, с тёмной обводкой текста (`'text-outline-color'`, `'text-outline-width': 2`) — читается на любом фоне.
- **Рёбра**: `width: 0.6`, `'line-color': '#9fb4ff'`, `'line-opacity': 0.35`, `'curve-style': 'bezier'`; рёбра, соединяющие защищённые ноды (бэкбон), — `line-opacity 0.6`, `width 1`.
- Фон холста — тёмный радиальный градиент в CSS контейнера (`styles/modules/memory-graph.css`), без картинок.
- **Качество отрисовки** (ориентир EVE): при создании Cytoscape `pixelRatio: 'auto'` (чёткость на HiDPI), `textureOnViewport: false`, `motionBlur: false`, `hideEdgesOnViewport: false` — качество важнее скорости при наших размерах (сотни нод). Если на 500+ нодах станет тормозить — включать `textureOnViewport` только при `cy.nodes().length > 400` (одно число, константа с комментарием).

### 4.3 Фон-зоны вместо дартса (Б1, пункт 7)
- Удали использование `renderRegionBackgroundSvg` (функцию можно оставить в `legacy-geometry.js`, на неё тесты).
- Новый `cores/ui/memory-graph/zones-svg.js`: `renderZonesSvg(zones, { size })` — SVG со слоем зон: у каждой зоны путь `zonePath(zone)` с заливкой `hsla(hue, 60%, 55%, 0.06)` и контуром `hsla(hue, 60%, 65%, 0.25)`; подпись по внешней дуге: `label` и `count/capacity` мелко (например `Kira's family · 12/23`); у зоны накопителя подпись `Unplaced · N`.
- Перерисовывать SVG, **когда меняется набор зон** (сравни сериализацию зон), не на каждый pan/zoom; положение при pan/zoom — тем же `backgroundTransformCss` (уже работает).
- Зона под курсором при перетаскивании — подсветка контура (класс/атрибут на пути, CSS `stroke-opacity: 0.8`).

## Этап 5. Визуализация ретрива (пункт 4)

1. Окно подписывается на `memoryGraph.retrieved` (как на остальные события — найди, где окно подписывается на `memoryGraph.nodeCreated` и т.п.), при открытии окна читает `memoryGraph.lastRetrieval`.
2. Классы Cytoscape:

   - `.route` — рёбра маршрута (`segments`): `width 2.2`, `line-color #7aa2ff`, `line-opacity 0.95`, `line-style dashed`; на промежуточных нодах маршрута — `.route-node` (свечение слабее маяков);
   - `.noise` — шумовые ноды: тонкая обводка, свечение чуть сильнее обычного;
   - `.dimmed` — все остальные ноды и рёбра: `opacity 0.25`.
3. Поведение — **переключатель** в боковой панели **«Retrieval overlay: On / Off»** (по умолчанию Off, состояние запоминается вместе с остальным состоянием окна — найди `saveWindowState`). Включён — подсветка последнего ретрива видна постоянно и обновляется с каждым новым ретривом; выключен — граф без подсветки.
   **История (как «повтор» на карте EVE):** под переключателем — полоса из последних 20 ретривов (точки по времени, новые справа) и кнопки ◀ ▶. Выбранная точка показывает на графе ТОТ ретрив; «Live» — вернуться к следующему за последним. Выбор точки включает переключатель автоматически.
4. Анимация маршрута: бегущий пунктир по рёбрам `.route` — через `requestAnimationFrame` меняй `line-dash-offset` (≤ 30 кадров/с), только пока подсветка активна и окно видно; при `prefers-reduced-motion: reduce` — без анимации, только статичный пунктир.
5. Боковая панель, секция **«Retrieval»** (для выбранного в истории ретрива): время («12s ago»), `sticky` (пометка «reused»), список маяков (подписи-кнопки: клик — `cy.animate({ center: { eles: node }, zoom: … })` и выделение), цепочка маршрута текстом `A → C → B`, «+N noise», начало запроса (`query`).
6. Тесты: функция `retrievalClasses(lastRetrieval, allNodeIds, allEdgeIds)` → `Map(id → класс)` (чистая, в том же файле) — маяки, маршрут, шум, остальное `dimmed`; пустой ретрив — никаких классов.

## Этап 6. Режимы карты, метрики, легенда, фильтры (уровень карты EVE Online)

Идея как у звёздной карты EVE: одна и та же карта, но **режим** решает, что показывают цвет, размер и свечение; легенда всегда объясняет шкалу; фильтры и поиск помогают найти нужное; сводка показывает цифры.

### 6.1 Метрики — данные, а не код в стилях
Новый файл `cores/ui/memory-graph/metrics.js` (чистые функции):
```js
/**
 * Метрика: { id, label, description, value(node, ctx) → число | строка | null, scale: 'rank' | 'linear' | 'categorical', palette, format(value) → текст для легенды/подсказки, higherIsBetter }.
 * ctx — { regionsById, now, lastRetrieval } — всё, что метрике нужно кроме самой ноды.
 */
export const METRICS = [ … ];
export function metricColor(metric, value, domain) // → '#rrggbb'
export function metricDomain(metric, nodes, ctx)   // → { min, max } для linear, список категорий для categorical
```
Метрики (id → что показывает):
- `weight` — **по умолчанию**, `weightRank` (0–1), красный → янтарный → зелёный; защищённые — зелёный + белая обводка (обводку даёт стиль по `protectedNode`, не метрика);
- `risk` — риск вытеснения: `1 − weightRank`, но только для нод в регионах, заполненных ≥ 80% (`count/capacity`), иначе 0; палитра серый → красный. Подсказка: «Will be evicted first if <region> fills up»;
- `importance` — важность 0–10 от модели (прежний цвет);
- `connections` — `degree`, линейно, тёмно-синий → голубой;
- `age` — `ageTurns`, линейно, светлый (новые) → тёмный (старые);
- `idle` — `idleTurns` (давно не использовалась), зелёный (недавно) → серый (давно);
- `retrieved` — `retrievedCount`, 0 — серый, дальше — янтарный → белый («горячие» ноды);
- `region` — категориальная: цвет = `hue` зоны региона (этап 3), чтобы видеть границы регионов по нодам;
- `source` — категориальная: происхождение ноды. Посмотри, какие поля реально есть у нод разного происхождения (`wiUid` у органических из чата; поля от бутстрапа из лорбука и из карточки персонажа — найди в `bootstrapFromLorebook`/`createNodeFromCharacterCard`; ручные — `createNodeManually`). Если различить нельзя по существующим полям — добавь в Ядро при создании поле `source: 'chat' | 'lorebook' | 'card' | 'manual'` (у старых нод — `'unknown'`).
Палитры — последовательные (светлота меняется монотонно), читаемые на тёмном фоне; для «плохо → хорошо» — красный → янтарный → зелёный.

### 6.2 Три канала — три выбора
В боковой панели секция **«Map mode»**:
- **Color by** — выпадающий список метрик (по умолчанию `weight`);
- **Size by** — `connections` (по умолчанию, это пункт 2 запроса: размер = число связей, радиус и зазор — `nodeRadius`/`minCenterDistance` из этапа 3), `importance`, `retrieved`, `uniform`. Раскладка (этап 3) всегда считается по выбранному размеру — зазоры остаются верными в любом режиме;
- **Glow by** — `none`, `weight` (по умолчанию: сильнее вес — ярче свечение), `retrieved`, `risk`.
Быстрые пресеты кнопками (как вкладки режимов карты в EVE): **Health** (color weight, size connections, glow weight), **Eviction risk** (color risk, glow risk), **Usage** (color retrieved, size retrieved, glow retrieved), **Structure** (color region, size connections, glow none), **Timeline** (color age, size uniform).
Выбор сохраняется в состоянии окна.

### 6.3 Легенда
Угол холста (поверх, HTML, не Cytoscape): название метрики цвета, полоса градиента с подписями min/max (`format`) — или список категорий с цветными точками; строка про размер («Size: connections, 0 → 24»); про свечение. Обновляется при смене режима и данных.

### 6.4 Подсказка при наведении
Карточка у курсора: метка ноды, регион, и **все** метрики строкой (`Weight 0.71 · Importance 7 · Connections 5 · Age 34 · Idle 3 · Retrieved 12×`), плюс «Protected» / «Unplaced». Не путать с формой редактирования (та — по клику, как сейчас).

### 6.5 Фильтры и поиск
- Поле **Search**: подстрока в `label`/`content` → совпадения подсвечены (класс `.match`), остальное `.dimmed`; Enter — центрировать на первом совпадении, повторный Enter — на следующем.
- Флажки **Show**: `Protected`, `Ordinary`, `Unplaced`, `Edges`; ползунок **Min weight** (скрывает ноды с `weightRank` ниже порога — удобно видеть «скелет» графа).
- Фильтры скрывают через класс `.filtered` (`display: none`), раскладку НЕ пересчитывают — карта не «прыгает».

### 6.6 Сводка (как статистика системы в EVE)
Секция **«Stats»**: нод всего / защищённых / в накопителе; рёбер; средний вес; регионов; самый заполненный регион (`12/23`); сколько нод под риском вытеснения; последний ретрив «N nodes». По клику на регион в сводке — центрировать карту на его зоне.

### 6.7 Тесты (`tests/memory-graph-metrics.test.js`)
- `metricColor` для `weight`: 0 → красный, 1 → зелёный, 0.5 → янтарный;
- `risk` = 0 для нод в незаполненном регионе;
- категориальная `region` даёт одинаковый цвет нодам одного региона и разный — разным;
- `metricDomain` для linear-метрик = реальные min/max по нодам;
- фильтр `Min weight` не меняет позиции (позиции берутся из раскладки, фильтр — только классы).

## Этап 7. Перетаскивание, создание, соединение (пункт 6)

Новый файл `cores/ui/memory-graph/interactions.js` — обработчики, получает `cy`, текущие зоны и функции окна (`moveNode`, `createNodeAt`, `createEdge`, `deleteEdge`).

### 6.1 Перетаскивание
- `grab` → `draggingId`, подсветка зоны под курсором на `drag` (`zoneAt`).
- `free`:
  - зона та же → нода плавно возвращается на свою позицию из раскладки (`node.animate({ position }, { duration: 200 })`);
  - другая зона → `moveNode(id, zone.regionId)` (через `regionId`, этап 2); после ответа — `refresh()`; на экране короткая плашка «Moved to <label> · Undo» (Undo переносит обратно в прежний `regionId`; плашка сама исчезает через 5 с);
  - зона накопителя или пусто → вернуть на место, ничего не менять.
- Сброс `draggingId` в любом случае.

### 6.2 Создание ноды
- Кнопка **«+ Node»** включает режим создания (как сейчас), курсор-перекрестие; подсказка «Click inside a region».
- Клик в зону → форма создания с **выпадающим списком регионов** (по умолчанию — зона клика; можно сменить) → `createNode({ …, regionId })`.
- Дополнительно: **двойной клик по пустому месту зоны** — то же самое без кнопки.
- Клик вне зон в режиме создания — подсказка «Pick a region», форма не открывается.
- `Esc` — выйти из режима.

### 6.3 Соединение нод (Б4 — упростить)
Два способа, оба простые:
- **Shift + перетаскивание от ноды** рисует ребро: на `tapstart` по ноде с зажатым Shift → `eh.start(node)`; `ehcomplete` → `createEdge(source, target, currentEdgeType)`. На время соединения — отключить обычное перетаскивание ноды (`node.ungrabify()` / вернуть `grabify()` после).
- Кнопка **«Connect»** (режим): клик по первой ноде (она подсвечивается), клик по второй → ребро создано, режим остаётся для следующего; `Esc` — выход.
- Тип ребра — выпадающий список рядом с кнопкой: типы, уже встречающиеся в графе (собрать из `edges`), плюс `related` по умолчанию.
- Ребро между уже соединёнными нодами того же типа — не создавать, подсказка «Already connected».

### 6.4 Удаление ребра (Б5)
- Клик по ребру **выделяет** его (подсветка) и показывает над ним маленькую панель «type · Delete». Удаление — только кнопкой Delete или клавишей `Delete`/`Backspace` при выделенном ребре.

### 6.5 Тесты
Вынеси решения в чистые функции и тестируй их:
- `dropDecision(fromRegionId, zoneUnderPointer)` → `'snap-back' | { move: regionId }`;
- `connectModeStep(state, clickedNodeId)` → новое состояние + `{ create: [a, b] }` на второй клик; клик по той же ноде снимает выбор;
- `edgeTypesInGraph(nodes)` — уникальные типы + `related`.

## Этап 8. Документация и проверка
1. `ROADMAP.md` — запись: что было (Б1–Б5, фиксированный размер, нет ретрива, один цвет), что стало, числа по умолчанию (радиусы, зазоры, палитры, история 20 ретривов), чем проверено.
2. `MEMORY_GRAPH.md` — короткий раздел «Окно графа»: зоны = регионы, режимы карты и метрики, легенда, фильтры, ретрив и его история, управление (Shift-drag, Connect, двойной клик, Delete, Esc).
3. Ручная проверка в харнессе, скриншоты в отчёт:
   - граф с 3+ регионами: зоны с подписями, ноды разного размера, свечение;
   - перетаскивание в другую зону → нода переехала, Undo возвращает;
   - «+ Node» в семантической зоне → нода в этом регионе;
   - Shift-drag между нодами → ребро; клик по ребру → Delete;
   - ретрив (сгенерировать ответ или вызвать контракт ретрива из консоли харнесса) → при включённом Retrieval overlay маяки и маршрут подсвечены; история ◀ ▶ переключает прошлые ретривы;
   - каждый пресет режима карты (Health, Eviction risk, Usage, Structure, Timeline) — скриншот с легендой; поиск и фильтр Min weight.

## Чего НЕ делать
- Не менять алгоритмы Ядра (размещение/ретрив/слияние) — только API из этапа 2.
- Не зашивать метрики в стили Cytoscape — только `data(color|size|glow)`, считает `metrics.js`.
- Не пересоздавать все элементы Cytoscape на обновление.
- Не удалять старые экспортируемые функции, на которые есть тесты, — можно перестать их использовать.
- Не отключать и не пропускать тесты. Всё сомнительное, что заметишь по пути, — списком в конец отчёта, не чинить заодно.
